عیب یابی تحلیل نرم‌افزار خرید بلیت حمل‌ونقل عمومی
توضیح مسئله و نیازهای بیزینسی
در این پروژه، یک تحلیل اولیه برای سامانه خرید بلیت اتوبوس و مترو، کارت بلیت اعتباری، مشاهده برنامه حرکت، رزرو صندلی و مدیریت اشتراک‌ها انجام شده است. برخی بخش‌های تحلیل ناقص یا دارای ایراد هستند و باید توسط تحلیلگر بررسی، عیب‌یابی و تکمیل شوند.

نیازهای بیزینسی:

خرید آنلاین بلیت اتوبوس و مترو توسط کاربران
شارژ و مدیریت کارت بلیت اعتباری
مشاهده برنامه حرکت وسایل نقلیه عمومی
امکان رزرو صندلی و مدیریت اشتراک حمل‌ونقل
مدیریت تعاملات کاربران و ذی‌نفعان مختلف (اپراتور، راننده، پشتیبانی و ...)
هدف تحلیل: تحلیلگر باید تحلیل اولیه را با توجه به چالش‌های مشخص‌شده بررسی و با تکمیل یا اصلاح بخش‌های ناقص، یک تحلیل جامع و منطبق بر نیازهای واقعی کسب‌وکار ارائه کند.

چالش‌ها و خروجی‌های مورد انتظار
چالش1: Sequence Diagram
مفهوم: نمایش ترتیب تبادل پیام‌ها و تعامل بین اجزای سیستم و کاربران در یک سناریوی خاص به‌صورت زمانی.
بخش بیزینس: سناریوی خرید بلیت و رزرو صندلی توسط کاربر (از ورود تا دریافت تاییدیه).
خروجی مورد انتظار: دیاگرام sequence در قالب فایل drawio که کل فرآیند خرید بلیت و رزرو صندلی را به‌درستی و بدون نقص نمایش دهد. (در فایل questions/challenge1/sequence.drawio)
پوشش بیزینسی: کل فرآیند خرید بلیت و رزرو صندلی باید پوشش داده شود.
چالش2: Class Diagram
مفهوم: نمایش ساختار داده‌ای سیستم، کلاس‌ها، ویژگی‌ها و روابط بین آن‌ها برای مدل‌سازی اطلاعات اصلی.
بخش بیزینس: ساختار داده‌ای مربوط به مدیریت کارت بلیت اعتباری و اشتراک‌ها.
خروجی مورد انتظار: دیاگرام کلاس در قالب فایل drawio که تمامی کلاس‌های اصلی، ویژگی‌ها و ارتباطات صحیح را نمایش دهد. (در فایل questions/challenge2/class.drawio)
پوشش بیزینسی: فقط بخش مدیریت کارت بلیت اعتباری و اشتراک‌ها باید بررسی شود.
چالش3: SWOT Analysis
مفهوم: تحلیل نقاط قوت و ضعف داخلی و فرصت‌ها و تهدیدهای بیرونی سامانه با توجه به شرایط بازار و رقبا.
بخش بیزینس: کل سامانه خرید بلیت حمل‌ونقل عمومی.
خروجی مورد انتظار: جدول SWOT واقعی و کامل در قالب فایل md (در فایل questions/challenge3/swot.md)
پوشش بیزینسی: کل چرخه کسب‌وکار و سامانه باید تحلیل شود.
چالش4: Stakeholder Map
مفهوم: نمایش نقش‌ها و میزان تاثیرگذاری و ارتباط ذی‌نفعان کلیدی پروژه با یکدیگر.
بخش بیزینس: تعاملات و تاثیرگذاری بین کاربران، اپراتور، راننده، پشتیبانی و سازمان حمل‌ونقل.
خروجی مورد انتظار: دیاگرام نقشه ذی‌نفعان در قالب فایل drawio که نقش‌ها و روابط را به‌درستی نمایش دهد. (در فایل questions/challenge4/stakeholder_map.drawio)
پوشش بیزینسی: کل ذی‌نفعان اصلی سامانه باید لحاظ شوند.
چالش5: Intermediate SQL
مفهوم: نوشتن کوئری‌های SQL با سطح متوسط شامل JOIN، GROUP BY و Subquery برای تحلیل داده‌های فروش و اشتراک.
بخش بیزینس: تحلیل داده‌های فروش بلیت و اشتراک کاربران.
خروجی مورد انتظار: یک فایل md شامل ۲ کوئری واقعی و کاربردی برای تحلیل فروش و اشتراک (در فایل questions/challenge5/sql.md)
پوشش بیزینسی: فقط بخش تحلیل داده‌های فروش و اشتراک بررسی شود.
